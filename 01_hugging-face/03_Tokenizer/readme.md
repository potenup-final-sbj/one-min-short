## 📚 Chapter 01. 허깅페이스 생태계와 핵심 아키텍처 - 섹션 1.4 Tokenizer와 Model의 결합

### 🎬 도입 스토리

여러분이 아주 유능한 외국인 요리사를 채용했다고 가정해 봅시다. 이 요리사는 세상의 모든 재료를 완벽하게 요리할 수 있는 능력이 있지만, 한 가지 치명적인 문제가 있습니다. 바로 **한국어를 전혀 읽지 못한다는 것**입니다. 여러분이 "김치찌개 끓여줘"라고 적힌 쪽지를 주면, 요리사는 그 텍스트를 이해하지 못하고 멍하니 서 있을 뿐입니다.

이 요리사에게 일을 시키려면 중간에 '통역사'가 필요합니다. 통역사는 "김치찌개"라는 단어를 요리사가 이해할 수 있는 '재료 번호(ID)'인 `[102, 45, 88]`로 바꾸어 전달해야 합니다. 그래야 요리사는 102번 재료(김치)와 45번 재료(고기), 88번 재료(고춧가루)를 꺼내 요리를 시작할 수 있습니다.

AI의 세계도 이와 똑같습니다. 우리가 사용하는 딥러닝 모델(LLM 등)은 사실 거대한 수학 연산 장치에 불과합니다. 모델은 '안녕'이라는 글자를 처리할 수 없습니다. 모델이 이해하는 것은 오직 '숫자(텐서)'뿐입니다. 이때 텍스트를 숫자로 변환하여 모델의 입맛에 맞게 가공해 주는 핵심 컴포넌트가 바로 **Tokenizer(토크나이저)** 입니다.

개발자는 단순히 `tokenizer()`를 호출하는 것에 그치지 않습니다. 토크나이저가 단어를 어떻게 쪼개는지, 특수 토큰이 메모리 배치에 어떤 영향을 주는지, 그리고 **Attention Mask**가 왜 연산 효율성의 핵심인지를 명확히 이해하고 코드를 설계합니다. 

>[!note]
> Attention Mask란? <br>
> Attention Mask는 모델이 입력 문장에서 실제 의미 있는 단어와 패딩 토큰(`[PAD]`)를 구분할 수 있도록 돕는 이진 행렬입니다. 모델이 패딩 토큰에 불필요한 연산을 수행하지 않도록 하여 메모리 사용량과 계산 속도를 최적화합니다.

---
### 텍스트에서 숫자로의 여정

토크나이저는 세 가지 핵심 단계를 거쳐 문장을 변환합니다.

1. **Normalization & Pre-tokenization**: 공백 제거, 소문자 변환, 문장을 의미 있는 단위(단어 혹은 부분 단어)로 쪼개기.
   - 예: "Hello, world!" → ["Hello", ",", "world", "!"]
   
2. **Tokenization**: 쪼개진 단어들을 미리 정의된 사전(Vocab)에 있는 ID와 매칭하기.
   - 예: ["Hello", ",", "world", "!"] → [7592, 1010, 2088, 999]

3. **Post-processing**: 모델이 문맥을 파악하기 위해 필요한 특수 토큰(`[CLS]`, `[SEP]` 등)을 추가하고 텐서(Tensor)로 변환하기.
   - 예: [7592, 1010, 2088, 999] → [101, 7592, 1010, 2088, 999, 102] <br>101: `CLS`, 102: `SEP`


### 내부 동작 원리

**A. Vocab(어휘 사전)과 OOV 문제** <br>
모든 토크나이저는 내부에 `vocab.json`이라는 해시맵(Hash Map)을 가지고 있습니다.

* **OOV(Out-Of-Vocabulary)**: 만약 사전에 없는 단어(예: 신조어)가 들어오면 어떻게 될까요? 과거에는 이를 `[UNK]`(Unknown)로 처리하여 정보 손실이 컸습니다.
  
* **Subword Tokenization (BPE, WordPiece)**: 현대적인 토크나이저는 단어를 더 작은 단위로 쪼개어 이 문제를 해결합니다. 예를 들어 "Annoyingly"를 "Annoying" + "ly"로 쪼개면, 사전에 전체 단어가 없어도 의미를 보존하며 숫자로 바꿀 수 있습니다.

> [!note]
> OOV란? <br>
> OOV(Out-Of-Vocabulary)는 토크나이저의 어휘 사전에 없는 단어를 의미합니다. 예를 들어, "블록체인"이라는 신조어가 사전에 없다면, 토크나이저는 이를 처리하지 못해 `[UNK]` 토큰으로 대체할 수밖에 없습니다. 이는 정보 손실로 이어질 수 있습니다. <br>
> 이를 해결하기 위해 현대 토크나이저는 Subword Tokenization 기법을 사용하여 단어를 더 작은 단위로 쪼개어 처리합니다.

**B. Special Tokens: 모델을 위한 제어 신호** <br>
모델은 문장의 시작과 끝을 스스로 알 수 없습니다. 그래서 우리는 약속된 기호를 넣습니다.

* `[CLS]` (Classification): 문장 전체의 의미를 응축하는 토큰입니다. 보통 문장 맨 앞에 위치합니다.

* `[SEP]` (Separator): 두 문장을 구분하거나 문장이 끝났음을 알리는데 사용됩니다.

* `[PAD]` (Padding): 배치 처리를 위해 문장 길이를 맞추는 용도입니다.

**C. Attention Mask: 연산의 게이트웨이(Gateway)** <br>
컴퓨터는 효율을 위해 여러 문장을 한꺼번에 처리(Batch Processing)합니다.  이때 가장 긴 문장에 맞춰 짧은 문장 뒤에 `[PAD]` 토큰을 붙여 길이를 맞춥니다.

* **문제**: 모델이 의미 없는 `[PAD]` 토큰까지 연산하면 자원이 낭비되고 결과가 왜곡될 수 있습니다.

* **해결**: `Attention Mask`는 0과 1로 이루어진 행렬입니다. 실제 데이터가 있는 곳은 `1`, 패딩인 곳은 `0`으로 표시합니다. 모델은 이 마스크를 보고 **"0인 부분은 계산에서 무시해(Masking)"**라고 판단합니다.

#### 3. 메모리 및 실행 흐름 관점

우리가 `tokenizer("Hello", return_tensors="pt")`를 호출하면 내부 메모리에서는 다음과 같은 일이 벌어집니다.

1. **RAM 영역**: 입력 문자열이 CPU 메모리에 로드됩니다.
   
2. **L1/L2 캐시**: 토크나이저의 사전(Vocab) 데이터가 캐시 메모리에 올라와 텍스트를 스캔하며 ID를 매핑합니다.
   - L1 캐시: CPU 코어에 가장 가까운 초고속 메모리로, 자주 참조되는 데이터가 저장됩니다.
   - L2 캐시: RAM과 L1 캐시 사이에 위치한 중간 속도의 메모리로, L1 캐시의 용량이 부족할 때 데이터를 보관합니다.
  
3. **GPU VRAM**: 생성된 `input_ids`와 `attention_mask` 정수 행렬(LongTensor)이 GPU 메모리로 복사(Host-to-Device Transfer)됩니다.

4. **연산**: 모델의 첫 번째 레이어인 **Embedding Layer**에서 이 ID 값을 인덱스로 삼아 거대한 가중치 행렬에서 특정 행(Row)을 추출해 냅니다.

#### 4. 주의사항 및 베스트 프랙티스

* **Pairing(짝맞추기)**: 모델과 토크나이저는 반드시 **한 몸**이어야 합니다. `BERT` 모델에 `GPT` 토크나이저를 쓰면 숫자가 엉뚱한 의미로 매핑되어 모델이 쓰레기 값(Garbage In, Garbage Out)을 뱉게 됩니다.
  
* **Truncation(자르기)**: 모델이 수용할 수 있는 최대 길이(Max Length)가 정해져 있습니다. 이를 넘어서는 문장은 반드시 적절히 잘라야 메모리 초과(OOM)를 방지할 수 있습니다.
  
* **Return Tensors**: 파이토치를 쓴다면 반드시 `return_tensors="pt"`를 명시하여 리스트가 아닌 텐서 객체로 즉시 변환하는 것이 효율적입니다.


### 🎓 핵심 요약

**이번 섹션에서 배운 것:**

1. **토크나이저의 역할** - 텍스트라는 비정형 데이터를 모델이 연산 가능한 정형 데이터(숫자 텐서)로 변환하는 '통역사'임을 이해했습니다.
2. **Subword Tokenization** - 단어를 쪼개어 OOV 문제를 해결하는 현대 AI의 핵심 전략을 배웠습니다.
3. **Attention Mask의 수학적 의미** - 배치 처리 시 발생하는 패딩(Padding)이 모델의 연산을 왜곡하지 않도록 게이트 역할을 수행함을 파악했습니다.
