## 📚 Chapter 03. FastAPI를 활용한 AI 모델 서빙 - 섹션 3.4 성능 및 모니터링 기초

### 🎬 도입 스토리

어느 월요일 아침, 서비스 오픈 후 첫 주말을 보낸 여러분에게 마케팅 팀장이 찾아와 묻습니다. "주말에 광고를 태웠더니 사용자가 몰렸는데, 일부 사용자들이 응답이 너무 느리다고 불평하더라고요. 정확히 얼마나 느렸던 건가요? 그리고 서버가 버틸 수 있는 한계가 어디까지죠?"

주니어 시절의 저는 "음, 제가 테스트할 때는 빨랐는데요..." 혹은 "서버가 죽지는 않았으니 괜찮은 거 아닐까요?"라고 얼버무렸을지도 모릅니다. 하지만 시니어 개발자는 다릅니다. 시니어는 '느낌'이 아닌 '지표(Metrics)'로 대화합니다.

"지난 주말 평균 응답 시간은 150ms였지만, 상위 5%의 사용자(P95)는 모델 추론 병목으로 인해 2.5초까지 지연되었습니다. 현재 VRAM 점유율이 90%에 육박하니, 다음 광고 집행 전에는 모델 최적화나 서버 증설이 필요합니다."

이렇게 말할 수 있으려면, 우리는 코드 곳곳에 측정 장치를 심어두어야 합니다. 오늘은 시스템의 심장 박동을 체크하는 모니터링 설계와 모델 버전 관리 전략을 마스터해 보겠습니다.

---

### 성능 측정의 두 축: 지연 시간(Latency)과 처리량(Throughput)

* **지연 시간 (Latency)**: 하나의 요청이 들어와 응답이 나갈 때까지 걸리는 시간입니다. AI 서빙에서는 특히 '추론 시간'이 지연 시간의 대부분을 차지합니다.
  
* **처리량 (Throughput)**: 단위 시간당 서버가 처리할 수 있는 요청의 수입니다. (예: 초당 요청 수, RPS)

### 평균의 함정과 백분위수(Percentiles)

개발자는 '평균 응답 시간'이라는 단어를 경계합니다. 만약 100명 중 99명이 0.1초 만에 응답을 받고, 1명이 10초가 걸렸다면 평균은 약 0.2초입니다. 수치상으론 좋아 보이지만, 10초를 기다린 그 한 명의 고객은 이미 서비스를 떠났을 것입니다.

* **P95 / P99**: 전체 요청 중 가장 느린 상위 5% 혹은 1%의 시간을 의미합니다. <br> 실무에서는 이 '꼬리 지연(Tail Latency)'을 줄이는 것이 모니터링의 핵심 목표입니다.

>[!note]
> 꼬리 지연(Tail Latency)<br>
> 꼬리 지연은 전체 요청 중 가장 느린 응답 시간들을 의미합니다. 예를 들어, `P95 지연 시간은 전체 요청 중 95%가 이 시간 이내에 응답을 받았음`을 나타냅니다. 꼬리 지연을 줄이는 것은 `사용자 경험을 향상`시키는 데 매우 중요합니다. 왜냐하면, 사용자는 평균 응답 시간보다도 느린 응답에 더 민감하게 반응하기 때문입니다.
> - p95: 95번째 백분위수 즉 95번째 요청은 이 시간 이내에 응답됨 나머지 5%는 이 시간 이상 걸림
> - p99: 99번째 백분위수 즉 99번째 요청은 이 시간 이내에 응답됨 나머지 1%는 이 시간 이상 걸림 


### 미들웨어(Middleware)를 통한 전역 모니터링

FastAPI의 **Middleware**는 모든 요청과 응답의 중간에 끼어드는 '검문소' 역할을 합니다.

* **작동 원리**: 요청이 들어오는 시점의 타임스탬프를 기록하고, 응답이 나가는 시점의 타임스탬프를 뺌으로써 전체 소요 시간을 계산합니다.
  
* **OS/커널 관점**: 이 작업은 사용자 모드(User Mode)에서 수행되지만, 잦은 타임스탬프 호출(`time.now()`)은 시스템 콜을 발생시킵니다. 하지만 현대적인 OS에서 이는 무시할 수 있을 만큼 가벼운 작업입니다. 오히려 이렇게 수집된 데이터를 외부 시계열 데이터베이스(Prometheus 등)로 전송할 때 발생하는 네트워크 오버헤드를 더 주의 깊게 설계해야 합니다.

> [!note]
> `user mode`<br>
> 사용자 모드는 운영 체제에서 애플리케이션이 실행되는 영역을 의미합니다. 이 모드에서는 애플리케이션이 직접 하드웨어에 접근하지 못하며, 시스템 콜을 통해 커널 모드로 전환하여 운영 체제의 자원에 접근합니다. 사용자 모드는 보안과 안정성을 위해 제한된 환경을 제공하며, 일반적인 애플리케이션 코드가 실행되는 곳입니다.

### 모델 버전 관리(Model Versioning) 전략

AI 모델은 수시로 업데이트됩니다.

* **추적성(Traceability)**: 응답 헤더(Response Header)에 현재 추론에 사용된 모델의 이름과 버전을 포함시키는 것이 베스트 프랙티스입니다. 그래야 나중에 "특정 모델 버전에서만 발생하는 에러"를 빠르게 디버깅할 수 있습니다.
  
* **Side-by-Side 테스트**: 운영 환경에서 구버전과 신버전 모델을 동시에 띄우고 성능을 비교하는 A/B 테스트의 기반이 됩니다.

### 주의사항 및 베스트 프랙티스

* **비용(Overhead)**: 모니터링 코드가 실제 비즈니스 로직보다 무거워지면 안 됩니다. 로그를 너무 많이 남기면 디스크 I/O 병목이 발생하여 오히려 서버가 느려질 수 있습니다.
* **임계치 알람**: 단순히 수치를 보는 것을 넘어, Latency가 1초를 넘어가거나 VRAM 사용량이 95%를 넘으면 슬랙(Slack) 등으로 알람을 보내는 '자동화된 감시' 체계를 갖춰야 합니다.
